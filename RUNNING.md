# Як запускати

Звірено з кодом 18.09.2026. Перевіряється тестом
`tests/test_running_doc.py`: кожен прапорець `main.py` мусить бути в
таблиці нижче, і навпаки — вигаданого прапорця тут бути не може.

## Три способи

| спосіб | коли | команда |
|---|---|---|
| GUI | подивитись на мережу, покрутити параметри руками | `python gui.py` |
| CLI з конфігом | звична серія прогонів | `python main.py --config configs/Hanoi_1M.json` |
| CLI з прапорцями | замір, A/B, відтворюваний прогін | `python main.py --inp ... --seed 42 --sequential` |

Конфіг і прапорці **комбінуються**, і правило одне: **явний прапорець у
командному рядку сильніший за значення з файлу.** Інакше конфіг серії
мовчки затирав би `--seed`, яким цю серію й розрізняють. Невідомі ключі у
файлі пропускаються без помилки.

```
python main.py --config configs/balerma_15M.json --seed 7 --sequential
```
— візьме мережу, одиниці, тиск і бюджет із файлу, а зерно й режим
відтворюваності з командного рядка.

## Усі параметри

| прапорець | за замовчуванням | що робить |
|---|---|---|
| `--config` | немає | JSON із тими самими ключами; програє явним прапорцям |
| `--inp` | `InputData/Hanoi/Hanoi.inp` | файл мережі EPANET |
| `--costs` | `InputData/Hanoi/costs.csv` | таблиця цін: діаметр -> ціна за метр |
| `--units` | `mm` | одиниці діаметрів у таблиці цін: `in` або `mm` |
| `--hmin` | `30.0` | мінімальний припустимий напір, м |
| `--runs` | `1` | скільки незалежних прогонів провести поспіль |
| `--cores` | `0` | скільки ядер (островів); `0` = всі доступні |
| `--run_mode` | `analytical` | `analytical` — повний пошук; `fast_analytical` — лише свіп швидкостей і спуск, секунди замість годин |
| `--max_sims` | за класом мережі | бюджет симуляцій на **весь** прогін |
| `--time_limit` | з калібрування | ліміт часу на один прогін, с; `0` = без ліміту (зупинка лише за `--max_sims`) |
| `--seed` | немає | зерно RNG головного процесу; без нього прогін невідтворюваний |
| `--sequential` | вимкнено | один острів у цьому ж процесі; **єдиний побітово відтворюваний режим** |
| `--v_opt` | `1.0` | **зараз ні на що не впливає** — див. нижче |

### `--units` — найдорожча помилка

Таблиця цін Ханої в дюймах, Балерми — у міліметрах. Переплутати означає
отримати тиски порядку −10⁸ і прогін, який годину рахує нісенітницю.
Передпольотна перевірка це ловить і каже причину, але краще не
покладатись: одиниці таблиці цін і `.inp` мусять бути однієї системи.

### `--max_sims` і `--time_limit`

Якщо `--max_sims` не заданий, бюджет береться за класом мережі
(за кількістю труб):

| клас | труб | бюджет за замовчуванням |
|---|---|---|
| SMALL | < 50 | 1 000 000 |
| MEDIUM | 50-199 | 3 000 000 |
| LARGE | 200-999 | 3 000 000 |
| XLARGE | ≥ 1000 | 30 000 000 |

`--time_limit` без значення виводиться з **заміряної** швидкості
симулятора, тому точка зупинки залежить від завантаження машини. Для
заміру це погано, тому:

* `--sequential` без `--time_limit` автоматично знімає часовий ліміт —
  зупинка лише за симуляціями;
* для звичайного прогону можна поставити `--time_limit 0` явно.

### `--seed` і відтворюваність

Побітова відтворюваність вимагає **двох** речей: `--seed` і
`--sequential`. Причина не лише в RNG: порядок обходу множин із
рядковими ключами (імена вузлів) залежить від `PYTHONHASHSEED`, який
Python рандомізує на кожен процес. `main.py` це знає й **перезапускає
себе** з `PYTHONHASHSEED=0`, коли задано `--seed`.

Наслідок, про який варто пам'ятати при інструментуванні: після
`main.main()` у вашому скрипті не виконається нічого — процес
замінюється новим. Щоб цього не сталось, ставте `PYTHONHASHSEED=0` у
середовищі самі (так роблять усі стенди в `experiments/`).

Без `--sequential` острови біжать асинхронно, і порядок подій залежить
від планувальника — числа будуть близькі, але не однакові.

### `--v_opt`: ручка, яка нічого не робить

Заміряно (журнал, етап 26): `SeedFactory.calculate_ideal_d` рахує
«ідеальний діаметр за цільовою швидкістю» з витрати в **одиницях .inp**
(CMH для Ханої, LPS для решти), а формула чекає м³/с. Похибка 1000-3600×
по витраті, тому **всі** труби отримують максимальний діаметр за
будь-якої швидкості від 0.5 до 3.0 м/с. Отже `--v_opt` зберігається в
чотирьох місцях і не читається жодним обчисленням.

Прапорець лишається до того, як буде вирішено, лагодити евристику чи
прибирати її разом із ручкою. Поки що задавати його немає сенсу.

## Що з'являється після прогону

```
OutputDataExperiments/<дата_час>/
├── logs/run_<дата_час>.txt      повний лог прогону (UTF-8)
├── tables/
│   ├── solution_champion.csv    діаметри найкращого рішення
│   ├── optimized_network.inp    та сама мережа для EPANET
│   ├── engineering_report.txt   інженерний звіт
│   └── runs_summary.csv         підсумок серії (`--runs > 1`)
└── plots/
    ├── network_map.png          карта мережі з діаметрами
    └── convergence.png          збіжність
```

Тимчасові файли EPANET живуть у `_temp_sim_data/run_<pid>` і прибираються
самі. **Два прогони з однієї теки можна запускати одночасно** — з етапу
28 вони не заважають одне одному; доти другий падав із
`PRE-FLIGHT CHECK FAILED`.

```
python -m pytest -q                       # тести
```

## Вимірювальні стенди

Лежать в `experiments/`, керуються змінними середовища й **не змінюють
продукційний код** — усе через підміну методів. Кожен перевіряє сам себе:
у контрольному режимі мусить дати еталонні числа побітово.

| стенд | питання | ключові змінні |
|---|---|---|
| `mechanism_census.py` | чи механізм виконується, скільки коштує, чи не холостий | `NET`, `SEED`, `SIMS`, `OUT`, `PARALLEL` |
| `ablation_probe.py` | що механізм дає якості пошуку | `ABLATE` (`none` = контроль) |
| `round_rule_ab.py` | правило ширини раунду проти вимкненого | `ROUND_SHARE` (`off` = контроль) |
| `round_size_probe.py` | чи краще багато дешевих раундів | `SHRINK`, `KICKS` |
| `seed_cost_probe.py` | куди йдуть симуляції стадії насіння | `NET` |
| `seed_depth_probe.py` | скільки проходів потрібно спуску насіння | `NET` |
| `polish_depth_probe.py` | глибина поліровки кандидата | `PASSES` |

Приклад (PowerShell):

```powershell
$env:PYTHONHASHSEED=0; $env:NET="Balerma"; $env:SEED=1; $env:SIMS=150000
$env:ROUND_SHARE="off"; python experiments\round_rule_ab.py
```

Приклад (bash):

```bash
PYTHONHASHSEED=0 NET=Balerma SEED=1 SIMS=150000 ROUND_SHARE=off \
    python experiments/round_rule_ab.py
```

## Синтетичні мережі-полігони

```
python experiments/make_grid_network.py --rows 16 --cols 16
```

Робить сітку в `InputData/Grid16x16/` з таблицею цін Балерми. Відбір у
вузлі підібраний так, щоб обмеження тиску було **тісним**: за початкових
0.35 л/с сітка виявилась виродженою — рішення «всі труби найтонші» вже
допустиме, і шукати нема чого.
